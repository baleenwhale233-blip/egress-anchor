## 当前实现

公开入口：[service_policy.py](../egress_anchor/service_policy.py) 的 `parse_service_policies`。
输入是服务记录列表，返回不可变的服务策略；它不读取订阅、磁盘、控制器或网络。

| 字段 | 当前契约 |
| --- | --- |
| id / name | 稳定服务 ID 与显示名分开；重命名不改变出口引用；重复 ID 拒绝 |
| exit.kind | inherit / direct / airport / isp；沿用订阅和直连无需资源引用 |
| exit.reference | airport 为原节点/组的精确名称，isp 为资源 ID；引用是否存在由后续生成器检查 |
| domains | 已合成的编译输入，普通域名覆盖自身及子域；不将模板数据和用户持久化数据合并存储 |
| exclude_domains | 只排除当前服务的匹配，不生成直连策略；不在当前模板内的排除项也保留 |
| strict | 各服务独立，默认 false；沿用订阅不能同时声明本工具严格保护；记录开关不代表已执行保护 |

域名统一大小写、末尾根点和 IDNA，并去重；URL、端口、IP、通配符及规则片段拒绝进入域名字段。
两个独立服务的域名范围相交时给出冲突服务 ID，避免靠列表顺序决定出口；合法排除可以消除冲突。
沿用订阅的记录不独立占有域名。所有输入错误使用固定信息和字段位置，不回显原始输入。

这是编译边界的规范化模型，尚未提供模板目录、DeepSeek 模板预选、持久化字段、自动域名更新或
Mihomo 规则输出。尤其没有将现有编译器的 UDP 缺口标为已修复。

## 维护边界

此模块为服务域的 L1 纯校验能力，包含它自己的不可变输入记录；不依赖 gateway、server 或客户端适配。
没有新增公共杂项类型库或空目录，也没有为了开始 P1 重写旧编译器和前端。
文件约 200 行，职责仍是同一输入边界；模板与规则生成另有变化原因，后续按其真实职责增加模块。
现有混层大文件和 `.four-layer.json` 的安排继续按 [F008](F008-维护与分层.md)。
