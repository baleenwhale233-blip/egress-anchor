## 已实现

- `/` 为服务首页，`#landings` 为落地代理，`#settings` 为订阅和客户端设置；原有页面移至 `/legacy`。
- 内置 Claude、ChatGPT（包含 Codex 约定入口）、DeepSeek，以及简单自定义服务。
  初始全部沿用订阅，DeepSeek 不自动改成直连。
- 沿用订阅、直连、仅走机场、指定 ISP 四类出口；高级域名、排除项、重叠冲突校验。
  模板域名与用户增补分开保存，编译时合成；服务 ID、名称、引用与修订分离。
- 单服务保存/删除的 HTTP API、持久化与过期修订保护；修改失败保留草稿。
- 服务优先规则、指定 ISP 的前置 → 落地 TCP 链、明确的服务 UDP 拒绝。
  排除域名交回原订阅处理；原规则相对顺序和无关策略组保持。
- 落地代理单条地址/手填、增删改和引用提示；密码不回传，编辑留空保留。
- 订阅导入、改名、选择、删除、生成和复制地址；本地生成与客户端应用分开显示。

## 状态和限制

保存成功不等于客户端已应用。生成后显示“待客户端更新”；未生成显示“已保存”；
检测详情的实际出口、代理链、服务、DNS、UDP/WebRTC 五项均显示“未验证”。
客户端自动发现/应用、完整严格模式、自动检测和独立恢复仍属后续批次。
严格开关不可开启，API 也拒绝请求开启，避免页面之外产生虚假保护状态。

“仅走机场”只列出可确认不含直连的固定节点及固定引用策略组。
provider/dynamic 组可能在空集合时回落或引入生成的落地节点，本批保守拒绝；旧版接管的组也不列出。
模板只声明首方域名，第三方登录、支付、遥测和未来新增域名不能据模板推定覆盖。

订阅切换后可逐项修复多个失效引用。单项合法修复先保存为待生成状态，直到所有引用有效才更新订阅；
期间保留上一份有效配置。新提交的失效引用、域名冲突、编译错误和磁盘提交失败拒绝发布。
返回沿用订阅也需要客户端更新，不能在保存后立即显示已恢复运行路径。

本批只修复新服务编译入口的 ISP UDP 约束。旧策略组编译入口的 UDP 基线缺口仍存在；
拒绝已匹配服务的 UDP 不等于完整严格模式，也不证明 DNS/WebRTC 或真实客户端 TUN 行为。

## 模块和维护

- `service_policy.py`：已有的不可变模型、域名与冲突校验。
- `service_catalog.py`：模板、用户记录变更、修订和公开状态计算。
- `service_compiler.py`：资源引用校验、服务规则和对旧编译入口的组合。
- `gateway.py`：在既有锁和原子存储边界内协调变更与生成，未增加共享状态 mixin。
- `server.py`：薄 API 入口和明确的静态文件白名单，不开放通用目录访问。
- `static/`：入口、样式、API、公共抽屉、三个视图和服务编辑分别维护；无新增运行依赖。

大文件过渡安排继续按 [F008](F008-维护与分层.md)，不声称全库已通过四层结构审计。
