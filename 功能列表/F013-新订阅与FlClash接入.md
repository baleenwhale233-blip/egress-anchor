# F013 新订阅与 FlClash 接入

日期：2026-11-04（Asia/Shanghai）。状态：本轮受控范围验证完成，P0 整体仍未通过。

本轮只修改隔离夹具和文档，不访问日常客户端配置。此前结果见 [F012](F012-P0覆写优化.md)。

## 已确认的决定

- 用户选择：FlClash 首版保留手动启动提示，暂不自动恢复运行；不为此增加辅助功能权限。
- 用户本机应用包元数据为 FlClash 0.8.94 / build 2026071102；只读取 Info.plist，未读取其配置。
  此前 Linux 0.9.2 结果不能作为该版本兼容结论，0.8.94 现加入隔离验证目标。
- 0.8.94 使用 schema 2、overwrite_type 与 profile_rule_mapping；0.9.2 使用 schema 21。
  不得把新版 SQL 直接写入旧版数据库。

界面差别主要来自版本跨度：官方 0.8.97、0.9.1 记录了界面和仪表盘重设计，见
[更新记录](https://github.com/chen08209/FlClash/blob/7fd417fb9a9a277c6a9339a8ac87f907df7c25f7/CHANGELOG.md)。
补测的 Linux 0.8.94 包版本为 0.8.94+2026071102，与用户应用包 build 一致；同版本布局接近。
测试账户的语言、主题、仪表盘状态及关闭系统代理/TUN，也不能当作平台缺少功能的证据。

## 实现与范围

- Verge 全局脚本在未登记订阅执行用户代码前先拒绝服务；登记原生静态保护后，继续原生生成。
  已有订阅保持热应用；本轮首次选中未登记订阅采用一次受控重开，不能记为全程无重启。
- FlClash 标准模式保留原生规则生成，只新增自有全局/逐订阅拒绝行；原脚本独立包装，不改 profile 模式。
- 默认新标准订阅先受全局拒绝保护；后台观察原生重建后热启用同一落地。
  后台退出时继续拒绝，不能依赖“先绕出、再补写”。
- 恢复只撤销自有记录和脚本，保留新订阅与后续更新；关闭自动运行时输出手动启动提示。

验证限定：Linux ARM64、规则模式、单个明确控制器、本地合成服务/前置/HTTP 落地。
本轮系统代理、TUN 关闭，通过原内核混合端口发流量，不代表已验证系统级接管或真实 AI。
业务代码与产品界面尚未接入这些流程。

### 连续采样

两次均在 30 秒窗口内由原客户端执行更新，采样本次 TCP 源端口对应的实际链路。

| 客户端 | 成功且经过落地 | 被拒绝请求 | 路径未验证的成功 | 观察到的成功绕出 | 无关既有长连接 |
| --- | ---: | ---: | ---: | ---: | --- |
| 0.9.2 | 813 | 13 | 0 | 0 | 保持 |
| 0.8.94 | 744 | 13 | 0 | 0 | 保持 |

报告为 next-flclash-transition-b6、next-0894-transition-b7。
13 是采样请求数，不是 13 次独立暂停；本地高频采样不能推定真实网络恢复时长或所有请求无失败。
无关 UDP 阳性对照只证明可用性，不证明无关 UDP 仍走代理或没有泄露。

## 旧版脚本模式的边界

官方 0.8.94 Linux ARM64 DEB 未包含 libquickjs_c_bridge_plugin.so。
模拟已有用户脚本时，原生基线就报缺库，控制器未初始化，因此该组合用例**未通过**。
没有用手工拼装的第三方运行库把它改记为客户端兼容通过。
此版本采取独立解包方式；另核对官方 control/postinst，安装脚本只建立启动软链接，没有安装该桥接库。

接入现在先做脚本引擎/原生控制器预检，缺能力时在写收据和停止客户端前拒绝。
next-0894-script-preflight 证明缺库被拒绝、收据不变；原失败基线报告也保留，未覆盖成成功。
合成脚本用例已清理，最终标准配置恢复并通过流量验证。此结果不代表 macOS 0.8.94 的脚本能力。

- 原有 139 项回归通过（26.395 秒），P0 31 项回归通过；SQLite 连接警告也已消除。
- P0 42 个 Python 文件语法通过，最大 186 行；共享 JS 语法和本地文档链接另验。

  包含一个旧版脚本基线失败，不能把报告数当成通过数。
- next-native-final-state 确认：两版自有拒绝行均为 0，原用户规则仍在；新版保留 3 份订阅、旧版保留 2 份；
  Verge 所有自有扩展文件逐字节还原。所有故障注入、模拟脚本与活动覆写已清理，恢复收据保留用于审计。
- 已正常停止测试客户端与 VM，未改日常 macOS 客户端，仅为确认版本读取了其应用包元数据。

存储版本差异放在 L1 规则存储能力，共用一份配置生成；L2 分别协调接入、跟随与恢复。
恢复收据不包含整库回滚，没有为这次实验改写 GatewayService 或新增应用框架。

## 仍未满足的 P0 / 产品条件

- macOS 专项未验；空间预算未满足，用户选择本轮只预检，不创建 macOS VM。
- 系统代理/TUN 接管、真实 AI、DNS/WebRTC、普通模式 UDP 未验；旧业务编译器的未加固 UDP 缺口仍在。
- 旧版 Linux 原脚本模式缺依赖；任意原脚本、原生自定义模式、外部 provider、升级和备份导入未完整验证。
- Verge 新订阅保护依赖有效全局挂载；整段挂载丢失、输入大小/运行限制导致整个全局钩子跳过等情况，
  不能泛化为本轮已解决。首次已切入未登记订阅的登记当前有重开影响，产品必须提前说明。
- 并发、多客户端身份、原生缓存/导出与 UI 通知、前置自动登记及完整失败重试仍需补齐。
  当前仍为 P0 原型，没有把这一轮局部通过记为完整严格模式或完整客户端支持。
